# Partition route failures without hiding data integrity errors

Collection: catalog · ID: `next-lab-failure-isolation` · Mode: **guided**

## Business context

A notification outage turns every account page into a blank loading screen indefinitely.

## Task

Design the system for Dashboard with billing, reports and notifications; dependencies have independent SLOs. Produce the component/data-flow diagram, request and mutation contracts, cache/trust boundaries, capacity assumptions, failure recovery and rollout gates. State which decisions change between Next.js 15 and 16 instead of using a framework API as a substitute for an architectural guarantee.

## Candidate tasks

- Draw components and annotate ownership of data, identity, caches and durable work.
- Specify contracts/schema and quantify the capacity/freshness assumptions.
- Walk through the failure scenario and design measurable acceptance tests.
- Compare the reference decisions and answer the changed-requirement interview prompt.

## Constraints

- Keep essential navigation usable.
- Define which partial failures are tolerable.
- Preserve error ownership, retry and cancellation.

## Follow-up questions

- Should Promise.allSettled replace every error boundary?
